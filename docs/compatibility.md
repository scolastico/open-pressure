# Compatibility

**Omron X7 Smart AFib HEM-7380T1-EOSL is the tested monitor.** The user reports version 0.1.13 working. Detailed supplied evidence confirms profile registration, correct clock and manual history import, including a complete 111/111-record transfer, on this model. Android companion approval was also confirmed on Pixel 9 Pro, Android 17, after enabling Bluetooth. This does not establish every background timing, notification, export or UI path on every phone.

Other Bluetooth blood pressure device families are expected to work where they expose an implemented protocol, but are **untested**. Marketed names such as Evolv, M4/X4, other X7/M7, RS7 or HeartGuide cover different firmware and service layouts. Selecting a model hint does not authorize a memory map or establish support for every variant.

| Protocol or feature | Implementation and evidence |
| --- | --- |
| X7 plain WLP, HEM-7380T1-EOSL | Tested registration (including its clock) and manual history; settings/index read and validated END confirmed. The standalone Sync clock is confirmed on this exact model (2026-10-18, plain connection) |
| X7 accepted DIS identities | Exact `HEM-7380T1`, `HEM-7380T1-EOSL`, `HEM-7380T1-EBK` and, case-insensitive, `X7 Smart AFib`. EBK's original assets match EOSL apart from the model ID. Registration is confirmed only on the EOSL label; on HEM-7380T1-EBK it is untested and available only through a hidden developer option for validation, and a bare `HEM-7380T1` never registers. These aliases do not establish testing of another variant. |
| X7 encrypted WLP1COM_PAIR | Implemented application handshake, saved-key reconnect and explicit cuff authorization; synthetic tests against a simulated encrypted peer, no captured-device interoperability confirmation. Selected for cuffs advertising encryption or with a saved application key; a plain-advertising cuff reaches it on Pair only through a hidden experimental developer option. No registration on this route; Sync clock over it only through a second experimental option. Hardware-untested and may simply fail |
| Standard BP Service `1810 / 2A35` | Implemented and parser-tested; other physical monitors untested |
| Omron Optional Service RACP | Implemented count/report and sequence-filter history; physical monitors untested |
| User Data Service | Implemented user consent/registration; physical monitors untested |
| Current Time / Omron Date Time | Implemented explicit writes on supported standard profiles; physical monitors untested. Vendor-memory imports no longer write them |
| Sync clock (clock-block write) | Implemented for HEM-7150T, HEM-7155T, HEM-7156T, HEM-7342T, HEM-7361T, HEM-7530T, HEM-7600T, HEM-6232T and plain-WLP HEM-7380T1-EOSL/EBK (including the `X7 Smart AFib` name, but not a bare `HEM-7380T1` identity) from source-derived [layouts](protocol.md#clock-block-layouts), synthetic tests and sandbox fixtures. **Confirmed on HEM-7380T1-EOSL** (`X7 Smart AFib`, plain connection) as of 2026-10-18, where it is offered without any developer option. **Untested on every other listed model**, including HEM-7380T1-EBK, so there it is available only through a hidden developer option for validation. Blocked on HEM-7322T and HEM-7377T1 (no documented clock block); not offered on encrypted X7 connections except through a hidden experimental developer option (hardware-untested) |
| STP secure handshake | Independent Java implementation, standard crypto vectors and synthetic peer tests; physical monitors untested |
| Automatic imports | Saved, bonded plain X7 and vendor-memory monitors advertising a type 1/2/6 record summary; vendor models also need a saved application key where they use one. Visible/notification/companion policies are implemented and tested in software. Only the X7's advertisement has been captured; exact timing/lifecycle paths require phone/cuff checks. Encrypted X7 and standard-profile monitors stay manual. |
| X7 AFib | Separate nullable flag decoded from original EOSL map; comparison with monitor results still required |
| Health Connect | Optional one-bank BP write export, off by default; API/worker tests, provider permission/export flows need phone validation |
| Legacy vendor memory | HEM-7150T, HEM-7155T, HEM-7156T, HEM-7322T, HEM-7342T, HEM-7361T, HEM-7530T, HEM-7600T, HEM-6232T: model-bound key provisioning/unlock and read-only history, manual or automatic. HEM-7150T, 7155T, 7156T, 7342T, 7361T, 7530T and 6232T read the monitor's index and then only populated slots, falling back to every slot when the index is untrusted; HEM-7322T and HEM-7600T always read every slot. Two-user models import User 1, User 2 or both; HEM-7156T imports one user, and Read all also tries its unconfirmed second bank. Record checksums are checked on every model except HEM-7322T. Source-derived maps, synthetic tests and Omron-sandbox agreement (except HEM-7322T, which no fixture covers); hardware-untested here, including 56-byte reads and index contents |
| BP5360 vendor memory | HEM-7377T1: OS bond, single channel, distinct record starts and metadata user attribution; always reads every slot, keeping readings of the chosen users by their record marker; manual or automatic history; implemented and source-validated, hardware-untested here |
| Other WLP, WLP1COM or WLP4COM models | Unknown models and layouts rejected before memory commands |
| GLS_EX `504A / 504B` | Not decoded as BP: the inspected analyzer exposes glucose fields |
| ECG, pulse oximetry, scales, thermometers, HeartGuide activity | Outside this blood pressure implementation |
| Omron cloud, paid services and reminders | Not implemented |

Release 0.3.0 adds the vendor readers above. Added protocol implementations do not expand the set of hardware-tested monitors. Language availability does not imply a translation has been reviewed by a native speaker.

Owners of untested monitors can share a [device report](device-reports.md); it is the preferred starting point for a support request. See [protocol selection](protocol.md#protocol-selection), [safety boundaries](safety.md) and [hardware validation](hardware-validation.md) before investigating another device. Unknown protocols and memory maps remain blocked rather than being inferred from a similar product name.

The [omblepy source comparison](omblepy-comparison.md) lists each record map and accepted identity. Base HEM-7156T uses the same read layout as HEM-7155T. Discovery accepts `BLESmart_…` and other letter-case variants of `BLEsmart_…`; identity verification still happens after connecting. Pair imports history on the same connection, following the monitor's saved **Readings to import** choice, then sends END without any clock write; the clock changes only through the explicit Sync clock above. Added vendor paths do not implement unread-counter resets or unrestricted EEPROM dumps. A complete standard BP/Optional Service profile retains priority when both layouts are exposed; mixed-profile devices need hardware validation.
